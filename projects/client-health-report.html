Client Health Report

Weekly at-risk account review for a CS team

Built and tested on fictional data, not deployed. Synthetic accounts; the report is internal and never goes to clients.

Problem

A Customer Success Manager has to check adoption, usage, tickets, contact history and renewal dates before deciding who needs attention. Reviewing this manually is slow, and important signals can be missed.

This workflow produces a weekly internal report: accounts are scored with fixed rules, and an LLM only writes a short note for the top accounts.

How it works

  • Rule in code
  • AI step
  • Person decides
  • Input or storage
  1. InputEvery Monday or on demand: read account data
  2. Rule (code)Risk score from fixed business rules
  3. Rule (code)Sort by risk level, then revenue; select the top three
  4. AI (Claude)Claude writes a short internal note for each of the three
  5. Rule (code)Combine into one report that also states how many accounts are high-risk
  6. PersonSaved as pending review; nothing goes to a client

Test results

This project has no test-results file and no automated evaluation. The only evidence is one sample run, kept in the repository.

EvidenceResult
Sample run on fictional data6 of 24 accounts high-risk; top 3 shown by risk level and revenue
Automated test set for note qualitynot built yet (listed as a next improvement)

What did not pass the first time, and what I changed

Successful run, blank output.

Nodes were connected in the wrong order: the workflow showed success, but the model received an empty record. I fixed the order and now check the output as well as the status.

Changing response shape.

The model response could include a thinking block before the text. The code now reads only text blocks.

Unsupported wording.

One test added a phrase that was not in the data. I tightened the prompt and reviewed the next run.

Blind spot in prioritisation.

Sorting by score alone left the highest-revenue high-risk account out of the top three. I changed the sort order and added the high-risk count to the report.

Limitations

  • The scoring thresholds are examples and have not been calibrated against real churn.
  • Sorting by revenue can push a smaller account with an urgent renewal out of the top three; a real team would need to agree this rule.
  • A real deployment would need client data rules, access controls, monitoring and a clear approval owner.
