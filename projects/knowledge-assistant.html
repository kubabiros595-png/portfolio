Knowledge Assistant

Documentation answers with cited sources

Built and tested on fictional data, not deployed. Help articles of an invented product, written for this project.

  • n8n
  • Retrieval
  • Citations
  • Claude

10 of 10 answerable questions answered with a correct citation; 5 of 5 uncovered questions refused.

My role. I built this project with AI assistance. I defined what a trustworthy answer means here (sources, refusals, gap log), chose keyword search over vector search for this data, set the threshold rule and the citation rule, wrote the expected results for every test question and decided to replace two easy "not covered" questions with harder ones.

Problem

Support and onboarding teams answer the same product questions every day, and the answers already exist in the help center. An AI assistant can save that time only if it can be trusted.

So it must show where each answer comes from, say “I don't know based on the documentation.” when the articles are silent, and log those questions so someone can fill the gap.

How it works

  • Rule in code
  • AI step
  • Person decides
  • Input or storage
  1. InputQuestion from the chat or the evaluation workflow
  2. Rule (code)Keyword search over 43 article sections, keep the top 4
  3. Rule (code)Best match score at least 0.35?
    • no → “I don't know”, the AI is not called
  4. AI (Claude)Claude answers only from those sections and returns JSON with the cited section IDs
  5. Rule (code)Code checks: every cited section was actually retrieved; “not covered” is respected
    • unknown source, not covered or error → “I don't know”
  6. StoredAnswer with sources, and every question logged with its status

Test results

15 test questions go through the real workflow, including the real Claude call: 10 are answered in the docs and 5 are not. Two of those five deliberately share words with the docs, so they pass the score threshold and test whether the AI itself refuses.

Replay the test

Pick a test question from the first run and see its best match score against the threshold, which sections were retrieved, and whether it was answered or refused. N02 and N04 pass the threshold but are refused by the AI itself.

Runs in your browser on data copied from the CSV and test files in the repository. No API calls, no keys, no server.

What did not pass the first time, and what I changed

The first live call failed with “Bad request”.

The model did not accept a temperature setting. The workflow still answered “I don't know” and logged an AI error, which showed the fail-closed path works. I removed the setting.

The test was too easy.

In the first draft, all five “not covered” questions scored below the threshold, so the test never checked whether Claude refuses on its own. I replaced two of them with questions that share words with the docs.

Counting refusals honestly.

A refusal caused by an AI error now counts as a mistake, not as a correct refusal.

Limitations

  • Keyword search misses synonyms and paraphrases that share no words with the docs.
  • The threshold was chosen by looking at the scores of these same 15 questions.
  • The key-fact check is a text match; it shows the main fact is present, not that the whole answer is well written.
  • The citation check proves the sources were retrieved, not that every sentence is supported by them. A person should still review answers before they reach customers.
