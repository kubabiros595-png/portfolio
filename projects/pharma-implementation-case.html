Problem

At Nordvale (a fictional company), Medical Information enquiries from physicians, pharmacists and patients are triaged by reading. A possible adverse event can be hidden inside an ordinary question, for example a rash mentioned next to a question about painkillers.

Safety reporting timelines start when the company receives the information, so a case waiting in the ordinary queue is a compliance problem, not just a slow reply. Replies are copied from old answers with unclear versions, and there is no record of who approved what.

This is a full implementation case: discovery, solution design, the n8n build, tests, risk assessment, compliance notes, a user guide and a handover plan.

How it works

  • Rule in code
  • AI step
  • Person decides
  • Input or storage
  1. InputEnquiry form or webhook
  2. Rule (code)Mask personal data, then a second scan
    • data left → MI human queue, no AI call
  3. Rule (code)Adverse-event keyword rules (no AI)
  4. AI (Claude)Claude returns category, AE flag and the ID of an approved response (JSON)
    • AI error or invalid output → MI human queue
  5. Rule (code)AE flagged by rules OR by Claude?
    • yes → Drug Safety queue, no draft
  6. Rule (code)Route by category
    • complaint → Quality queue
    • off-label → senior MI reviewer
    • no approved answer → MI human queue
  7. Rule (code)Draft = approved text word for word, with source ID and version
  8. Rule (code)Code checks: citation exists and is approved, no personal data, no forbidden phrases
    • fail → MI human queue
  9. PersonPerson approves, rejects (reason required) or edits
  10. StoredAudit log of every routing and review decision

What did not pass the first time, and what I changed

Run 1: a product complaint went to the human queue instead of Quality.

Claude classified it correctly but replied with two JSON blocks, and the first parser expected exactly one. The fail-safe sent it to a person, so nothing was lost. I changed the parser to read every block: they must agree on the category, any AE flag wins, and different response IDs mean no draft. Tested on the exact failing reply, then re-ran.

Run 2: an off-label dose question was flagged as a possible adverse event.

Claude set the AE flag on a question about doubling the dose. The keyword rules did not fire, but either signal is enough, so it went to Drug Safety. I decided not to tune this away: making the model less sensitive to pass one case would raise the risk of a missed adverse event. In runs 1 and 3 the same enquiry was not flagged.

Before run 3: one test case used a real active substance name.

That broke the rule that the case uses no real medicines, so I reworded it (test set v2). The other 25 cases did not change.

Limitations

  • Portfolio case on a fictional company; built and tested, not deployed; not legal or medical advice.
  • 26 hand-written English test cases. The keyword rules and the test cases were written by the same person, so the rule result is an optimistic estimate.
  • Masking is rule-based and tuned to the formats in the test set. Real data would need wider patterns and likely a name-recognition step.
  • Three test runs only. The model's output on borderline wording varies between runs (see run 2).
  • The review form login, form UI and email sending were not part of the automated test.
